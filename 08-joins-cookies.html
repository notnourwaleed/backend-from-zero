JOINs & cookies

Real data is connected: users write reviews about trips. This chapter shows how tables point at each other, how to read them together with JOIN, and how cookies let the server remember small things.

Tables that point at each other

A review needs to say who wrote it and which trip it's about. Instead of copying the username and destination into every review, the review stores their IDs. A column that holds another table's ID is a foreign key.

db.js — the REVIEWS table
CREATE TABLE IF NOT EXISTS REVIEWS (
  ID INT AUTO_INCREMENT PRIMARY KEY,
  USER_ID INT NOT NULL,
  TRIP_ID INT NOT NULL,
  RATING INT NOT NULL CHECK (RATING BETWEEN 1 AND 5),   -- only 1 to 5 allowed
  FOREIGN KEY (USER_ID) REFERENCES USERS(ID),            -- must be a real user
  FOREIGN KEY (TRIP_ID) REFERENCES TRIPS(ID),            -- must be a real trip
  UNIQUE (USER_ID, TRIP_ID)                              -- one review per user per trip
)

MySQL now protects your data:

  • A review for trip 999 (doesn't exist) → error ER_NO_REFERENCED_ROW_2.
  • Deleting a trip that has reviews → error ER_ROW_IS_REFERENCED_2 (that's the 500 you saw in Practice 5.6).
  • The same user reviewing the same trip twice → ER_DUP_ENTRY.
  • Rating 7 → the CHECK fails.

Since the tables point at each other, create them in the right order in server.js: USERS and TRIPS first, REVIEWS last.

INNER JOIN: only rows that match

Read REVIEWS alone and you see numbers: “user 2 gave trip 1 a 5”. A JOIN glues the matching rows from another table onto each row:

SELECT t.DESTINATION, r.RATING
FROM TRIPS AS t
INNER JOIN REVIEWS AS r ON t.ID = r.TRIP_ID;
  • TRIPS AS t gives the table a short nickname (an alias). Then t.DESTINATION means “DESTINATION from TRIPS”.
  • ON t.ID = r.TRIP_ID is the matching rule: glue a review onto the trip whose ID equals the review's TRIP_ID.
  • INNER = keep only trips that have at least one matching review. Venice, Kyoto and Barcelona disappear.

LEFT JOIN: keep everything from the left table

What if you want all trips, even ones nobody reviewed? Use LEFT JOIN: it keeps every row of the left table (the one after FROM). Where there's no match, the review columns are NULL.

Using JOINs in your API

In a controller, a JOIN is just a longer SQL string. Use backticks so it can span several lines:

const getTripReviews = async (req, res) => {
  try {
    const query = `SELECT t.DESTINATION, r.RATING, u.USERNAME
      FROM TRIPS AS t
      INNER JOIN REVIEWS AS r ON t.ID = r.TRIP_ID
      INNER JOIN USERS AS u ON r.USER_ID = u.ID`;
    const [rows] = await db.query(query);
    return res.status(200).json({ data: rows });
  } catch (error) {
    console.error(error);
    return res.status(500).json({ message: 'Database error' });
  }
};

(Backticks are fine here because nothing from the user is inside. The moment you add a user value, use ?.)

Cookies: the server's sticky notes

A cloakroom ticket

When you leave your coat, you get a small ticket. Next time you come to the desk, you show the ticket and they know which coat is yours. A cookie is that ticket: a small piece of text the server gives the browser, which the browser automatically sends back with every next request to the same server.

The course uses a cookie to remember the last trip you looked at:

  1. You request GET /trips/3. The server answers with the trip and sets a cookie lastViewedTrip=3.
  2. Later you request GET /trips/last-viewed. The browser sends the cookie along. The server reads it and returns trip 3.
npm install cookie-parser
index.js
const cookieParser = require('cookie-parser');
app.use(cookieParser());   // without this, req.cookies is undefined!
Setting and reading
// set (before res.json!)
res.cookie('lastViewedTrip', String(id), {
  maxAge: 24 * 60 * 60 * 1000,  // how long it lives, in MILLISECONDS → 1 day
  httpOnly: true,               // JavaScript in the web page can't read it (protects against theft)
  secure: true,                 // only sent over HTTPS
  sameSite: 'lax'               // not sent with requests from other websites
});

// read (in another request)
const id = Number(req.cookies.lastViewedTrip);
Two gotchas
  • Cookies are always text. That's why you String(id) when setting and Number(...) when reading.
  • secure: true on http://. Browsers allow secure cookies on localhost, but some tools may not send them back over plain http. If your cookie doesn't come back while testing, try the request in the browser, or use secure: false while developing.
Practice 8.7

The course code says maxAge: 24 * 60 * 60 * 1000 with the comment “1 hour”. How long does the cookie really live?

1000 ms × 60 = 1 minute, × 60 = 1 hour, × 24 = 1 day. The comment is wrong — comments can lie, code doesn't!
