Chapter 2

How the web works

Before writing a server, you need a picture of what a server does. It's simpler than it sounds: something asks, the server answers.

Client and server

A client is whatever asks for something: a browser, a phone app, or Postman. A server is a program that waits for questions and answers them. Your backend is a server.

Think of a restaurant
  • You (the customer) = the client. You place an order.
  • The order = the request: “one pizza, no onions”.
  • The waiter = the route: hears the order and takes it to the right cook.
  • The cook = the controller: does the actual work.
  • The fridge = the database: where ingredients (data) are kept.
  • The plate that comes back = the response. If they don't have pizza, you get a polite “sorry, not available” — that's an error response.

Every single request follows this path. Keep this picture in your head for the whole course.

What's inside a request

PartWhat it isExample
MethodThe verb — what do you want to do?GET, POST, PUT, DELETE
URLWhere — which thing?/users/3
BodyExtra data you send (only for POST/PUT){ "username": "sara" }
HeadersSmall notes about the request (type of data, cookies…)Content-Type: application/json

The parts of a URL

http://localhost:5000/users/3?sort=name
  • localhost means “this same computer”. 127.0.0.1 is the same thing written as a number.
  • Port: a computer has many “doors”. Your server listens at one of them (like 3000 or 5000). Only one program can use a door at a time.
  • Route parameter: a changing part of the path, like the id. In Express you write it as /users/:id and read it with req.params.id.
  • Query string: optional extras after ?, read with req.query.

Methods = the four actions (CRUD)

Almost every app does four things with data: Create, Read, Update, Delete. Each has its own HTTP method:

ActionMethodURLExample meaning
Read allGET/usersGive me all users
Read oneGET/users/3Give me user 3
CreatePOST/usersHere's a new user (in the body), save it
UpdatePUT (or PATCH)/users/3Change user 3 (new values in the body)
DeleteDELETE/users/3Remove user 3

See the pattern? The URL says which thing (plural noun: /users, /trips), the method says what to do. That's called a REST API.

The response: status code + body

Every response has a status code — a 3-digit number that says how it went — and usually a body with data in JSON.

CodeNameUse it when…
200OKEverything worked (read, update, delete)
201CreatedYou created something new (POST)
400Bad RequestThe client sent wrong or missing data
401UnauthorizedWrong email/password, not logged in
403ForbiddenLogged in, but not allowed (e.g. not admin)
404Not FoundThe thing doesn't exist (user 999)
409ConflictIt already exists (email already used)
500Internal Server ErrorSomething broke on the server (database error, bug)
Easy way to remember

2xx = “yes, done” · 4xx = “you (the client) made a mistake” · 5xx = “I (the server) made a mistake”.

JSON: the language of APIs

Servers and clients send data as JSON (JavaScript Object Notation). It looks almost exactly like a JavaScript object, but it's text and it's stricter:

{
  "id": 3,
  "username": "lina",
  "roles": ["user"],
  "active": true,
  "manager": null
}
  • Keys must have double quotes: "username" (not username or 'username').
  • Text values use double quotes too. Numbers, true, false, null don't.
  • No comma after the last item. No comments. No functions.

In JavaScript you convert between the two:

const obj = JSON.parse('{"name": "sara"}');   // text → object
const text = JSON.stringify({ name: "sara" }); // object → text '{"name":"sara"}'

Good news: Express does this for you. express.json() turns the request body text into req.body, and res.json(obj) turns your object into JSON text. But you need to know what's happening — and you'll type JSON by hand in Postman.

Summary

  • The client sends a request: method + URL (+ body).
  • The server finds the matching route, runs the controller, maybe talks to the database.
  • The server sends a response: status code + JSON body.
