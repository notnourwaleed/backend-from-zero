Chapter 1

The JavaScript you need

You don't need all of JavaScript to build a backend. You need about ten things — and you will use them in every single file. Here they are, each with practice.

How the code playgrounds work

Write your code in the box, then press ▶ Run (or Ctrl+Enter). You'll see what it printed, plus Checks that tell you which parts are right. Your code is saved automatically in this browser.

1. Printing with console.log

console.log(...) prints something in the terminal. It is your best friend for finding bugs: when you don't know what a value is, print it.

console.log("Hello");          // prints: Hello
console.log(5 + 5);            // prints: 10
console.log("Total:", 5 + 5);  // prints: Total: 10
// Lines starting with // are comments. JavaScript ignores them.

2. Variables: const and let

A variable is a box with a name that holds a value.

const name = "Sara";   // const = this box will NOT get a new value
let age = 20;          // let   = this box CAN get a new value later
age = 21;              // OK, because age is let
// name = "Omar";      // ERROR: Assignment to constant variable.
Rule of thumb

Use const by default. Use let only when you know the value will change. Don't use var (it's the old way).

Template strings

Use backticks ` (the key under Esc) to put values inside text with ${ }:

const city = "Paris";
const price = 1200;
const text = `The trip to ${city} costs ${price}`;
console.log(text); // The trip to Paris costs 1200

3. Types: text vs numbers (very important!)

Every value has a type. The main ones:

TypeExamples
string (text)"hello", 'sara@mail.com', "5"
number5, 950.5, -1
booleantrue, false
undefined“no value was given” — e.g. a missing field
null“empty on purpose”

"5" (text) and 5 (number) are different. This matters a lot in backend, because everything that comes from a URL is text. When someone visits /users/3, your code gets "3", not 3.

const fromUrl = "3";
console.log(fromUrl === 3);          // false  (text is not a number)
console.log(Number(fromUrl) === 3);  // true   (Number() turns text into a number)
console.log(Number("abc"));          // NaN    ("Not a Number" — the text wasn't a number)
console.log(typeof fromUrl);         // "string"

Always compare with === (three equals: same value AND same type). Not equal is !==. Avoid == — it guesses and makes surprising mistakes.

Practice 1.2

What does "7" === 7 give?

One is a string, one is a number, so === says false. Use Number("7") === 7 to get true.

“Truthy” and “falsy” — the trick behind if (!username)

In an if, these values count as false: "" (empty text), 0, undefined, null, NaN, false. Everything else counts as true. So:

if (!username) {
  // runs when username is missing: undefined, "", null...
}

You'll write this in every server to check that the user sent all the fields.

5. Objects: one thing with many details

An object groups related values. Each value has a key (name). One row of a database becomes one object.

const user = {
  id: 1,
  username: "sara",
  email: "sara@mail.com",
  role: "admin"
};

console.log(user.username);   // "sara"   ← read with a dot
user.role = "user";           // change a value
user.age = 22;                // add a new key
console.log(user.phone);      // undefined (doesn't exist)
Wait — user is const, but I changed it?

Yes. const means the box always holds the same object. You can still change what's inside the object. You just can't do user = somethingElse.

6. Arrays: a list of things

An array is a list in order. Before you learn databases, your “database” will be an array of objects:

const users = [
  { id: 1, username: "sara", role: "admin" },
  { id: 2, username: "omar", role: "user" }
];

console.log(users.length);       // 2
console.log(users[0].username);  // "sara"  ← counting starts at 0!
users.push({ id: 3, username: "lina", role: "user" });  // add at the end

// Go through every item with a for loop:
for (let i = 0; i < users.length; i++) {
  console.log(users[i].username);
}

// Shorter way when you don't need the number i:
for (const user of users) {
  console.log(user.username);
}
Practice 1.5

Hint 1
The loop: for (let i = 0; i < users.length; i++) { ... }. Inside it, compare users[i].id === id.
Hint 2 (the classic mistake)
Don't put return null inside the loop! Then the loop stops after checking only the first user. Put it after the loop's closing }.

Useful array methods

Arrays have built-in helpers that do the loop for you. Each one takes a function that runs for every item:

const nums = [5, 12, 8];
nums.find(n => n > 6);        // 12           first item that matches
nums.filter(n => n > 6);      // [12, 8]      ALL items that match
nums.map(n => n * 2);         // [10, 24, 16] change every item
nums.findIndex(n => n === 8); // 2            position of the match (-1 if none)
nums.splice(1, 1);            // removes 1 item at position 1 → nums is now [5, 8]

7. Functions (and functions as values)

A function is a recipe: steps with a name that you can run any time. It can take inputs (parameters) and give back an output (return).

// Normal function
function addTax(price) {
  return price * 1.14;
}

// Arrow function — the same thing, shorter. You'll see this EVERYWHERE in Express.
const addTax2 = (price) => {
  return price * 1.14;
};

// If the body is just one return, even shorter:
const addTax3 = price => price * 1.14;

console.log(addTax(100)); // 114

The big idea: passing a function to another function

In JavaScript you can give a function to another function, so it can run it later. This is exactly what Express does:

app.get('/hello', (req, res) => {
  res.json({ message: 'Hi' });
});
// You're NOT running the arrow function now.
// You're saying: "Express, when someone visits /hello, run THIS function."

8. Destructuring: unpacking values

A short way to take values out of an object or array. You'll write this at the top of almost every route:

const body = { username: "sara", email: "sara@mail.com", role: "admin" };

// Long way:
const username = body.username;
const email = body.email;

// Destructuring — same result, one line:
const { username, email } = body;   // takes the keys with THE SAME NAMES

Arrays work by position instead of name:

const result = [ ["row1", "row2"], "extra info" ];
const [rows] = result;        // rows = the FIRST item → ["row1", "row2"]
const [rows2, info] = result; // first and second item

This is why database code looks like const [users] = await db.query(...) — the database gives back an array whose first item is the rows.

9. Fallback values with ||

a || b gives a if it's truthy, otherwise b. Perfect for “use the new value if they sent one, else keep the old one”:

const newName = undefined;  // the user didn't send a new name
const finalName = newName || "sara";  // → "sara"

10. Errors: try / catch

Sometimes code fails (the database is down, the data is wrong…). Without protection, the program crashes. try / catch says: “try this; if anything goes wrong, catch the error and do this instead.”

try {
  const data = JSON.parse("this is not JSON");  // this throws an error
  console.log("never printed");
} catch (error) {
  console.log("Something went wrong:", error.message);
}
console.log("The program keeps running!");

You can also throw your own errors: throw new Error("Something bad").

After deleting sara, the list has 2 users (omar id 2, lina id 3). users.length + 1 would be 3 — but lina already has id 3! Two users with the same id = big bug. That's why you look for the highest id instead. (Real databases do this for you with AUTO_INCREMENT.)
