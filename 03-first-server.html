Chapter 3 · course week 4

Your first Express server

Express is a package that makes building a server easy. In this chapter you build a complete users API in one file, with the data in a simple array.

Make the project

On your computer
  1. Make a new folder first-server and open it in VS Code (File → Open Folder).
  2. Open the terminal (Ctrl+`) and run: 
    npm init -y
npm install express
  3. Make a new file server.js. You'll fill it in during this chapter.

The smallest server, line by line

server.js
const express = require('express');   // 1. load the Express package
const app = express();                 // 2. create your app (your server)
app.use(express.json());               // 3. let the app read JSON bodies

const PORT = 3000;                     // 4. which "door" to listen at
const HOSTNAME = '127.0.0.1';          //    on this computer

app.get('/hello', (req, res) => {      // 5. WHEN someone sends GET /hello…
  res.status(200).json({ message: 'Hello world' });   // …answer with this
});

app.listen(PORT, HOSTNAME, () => {     // 6. start listening for requests
  console.log(`Server is running at http://${HOSTNAME}:${PORT}`);
});
  1. require('express') loads the package you installed with npm.
  2. express() creates the app. Everything else is added to app.
  3. app.use(express.json()) — without this line, req.body is undefined. Always add it.
  4. The port can be any free number, like 3000 or 5000.
  5. app.get(path, function) adds a route: a method + path, and the function to run. The function always gets two things:
    • req (request) — what the client sent: req.params, req.body, req.query
    • res (response) — what you use to answer: res.status(code).json(data)
  6. app.listen starts the server. The function runs once it's ready.

Run it

node server.js

You see Server is running at http://127.0.0.1:3000 and the terminal seems “stuck”. That's correct! The server is waiting for requests. Open your browser at http://127.0.0.1:3000/hello and you'll see the JSON.

The #1 beginner mistake

When you change your code, the running server does not notice. You must stop it (Ctrl+C) and start it again (↑ then Enter).

Or run it in watch mode and it restarts by itself every time you save:

node --watch server.js
Practice 3.1

Your first route

Add the GET /hello route, then press Run. When the server is running, use the request box below the code to send GET /hello — just like Postman.

Also try GET /goodbye: you get 404 Cannot GET /goodbye. That's Express saying “I have no route for that”.

Read all users: GET /users

Until Chapter 5, our “database” is an array in the file. (It resets every time the server restarts — that's why real apps use MySQL.)

A good habit from the course: always answer with the same shape of object, so the client knows what to expect:

res.status(200).json({
  status: 'success',
  message: 'Users retrieved successfully',
  results: users.length,
  data: users
});
Practice 3.2

Read one user: GET /users/:id

The :id in the path is a route parameter — a placeholder. For GET /users/2, Express puts "2" in req.params.id.

Remember Chapter 1: "2" is text! Turn it into a number with Number(req.params.id) before comparing with ===.

Always return when you answer early 
if (users[i].id === id) {
  return res.status(200).json({ data: users[i] });   // ← "return" stops the function here
}
// ... more code ...
return res.status(404).json({ message: 'User not found' });

Without return, the code keeps going and tries to send a second answer. You get the famous error “Cannot set headers after they are sent to the client”. One request = one response.

Practice 3.3
Hint 1
This is findUserById from Chapter 1, but instead of return users[i] you return res.status(200).json(...).
Hint 2
The 404 goes after the loop, not inside it.

Create a user: POST /users

For POST, the new data comes in the body: req.body. Steps:

  1. Take the fields out with destructuring: const { username, password, role } = req.body;
  2. Validate: if anything is missing → 400 and stop (return).
  3. Make the new object (with a new id) and push it.
  4. Answer 201 with the new user.
Practice 3.4
Experiment (after it works)

Put // in front of app.use(express.json());, press Run, and send a POST again. Read the error: “Cannot destructure property 'username' of 'req.body' as it is undefined”. Now you'll recognise it when it happens for real. Remove the // again.

Hint
{ id: users.length + 1, username, password, role } — writing just username is short for username: username.

Update a user: PUT /users/:id

PUT combines what you know: find by id (like GET one) + read the body (like POST).

Practice 3.5

Delete a user: DELETE /users/:id — find the bug!

Spot the bug 3.6

This DELETE route looks right, but deleting user 2 or 3 always says “User not found”. Run it, send the requests, and find out why. Then fix it.

Hint 1
Follow the loop by hand for id 3. First round: i = 0, the user's id is 1. Is it equal to 3? No… so what's the next line that runs?
Hint 2
The 404 return is inside the loop, so the loop stops after the first user. Same mistake as Chapter 1's Hint 2!

Test your real server with Postman

  1. Start your server: node server.js.
  2. Open Postman → New → HTTP (or click the + tab).
  3. Choose the method (GET, POST…) from the dropdown on the left of the URL bar, and type the URL: http://127.0.0.1:3000/users.
  4. For POST/PUT: click the Body tab → choose raw → in the dropdown on the right change Text to JSON. Then type your JSON, for example: 
    { "username": "lina", "password": "secret", "role": "user" }
  5. Click Send. Underneath you see the status (like 201 Created) and the response body.
  6. Save it into your collection with Ctrl+S so you can send it again later.
Common Postman mistakes
  • Body is undefined / 400 “missing fields” even though you typed a body → you left it on Text instead of JSON, so Express didn't read it.
  • “Error: connect ECONNREFUSED” → your server isn't running, or the port in the URL is wrong.
  • Cookies: Postman keeps them for you. Click Cookies (under the Send button) to see or delete them.
On your computer

Build server.js in your first-server folder with all five routes. Type it — don't copy-paste — your fingers learn too.

  • GET /users returns all users
  • GET /users/2 returns one user, GET /users/99 returns 404
  • POST /users creates a user (201) and refuses missing fields (400)
  • PUT /users/2 changes a user
  • DELETE /users/3 deletes a user, and GET /users shows it's gone
  • I tested each one in Postman
  • I restarted the server and noticed my changes were gone (the array resets!)

You restarted the server and all the users you created are gone. Why?

Memory is wiped when a program stops. To keep data for real, you need a database — that's Chapter 5.
