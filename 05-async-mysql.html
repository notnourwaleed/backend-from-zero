Chapter 5 · course weeks 5–6

Async & MySQL: saving data for real

The array “database” forgets everything on restart. Now you connect to MySQL. But a database takes time to answer — so first you need to understand async and await.

Why “async”?

Ordering food

When you order food, you don't stand frozen at the door until it arrives. You get a promise: “your food will come”. Meanwhile you can do other things. When it arrives, you continue.

Asking a database is the same. db.query(...) doesn't give you the rows immediately — it gives you a Promise of the rows. You use await to say “wait here until the promise is done, then give me the result”.

async function getUsers() {              // 1. "async" before the function…
  const [users] = await db.query('SELECT * FROM USERS');   // 2. …allows "await" inside it
  console.log(users);                    // 3. this runs only AFTER the rows arrived
}

Two rules:

  1. await only works inside a function marked async.
  2. If you forget await, you get the promise itself (an empty “coupon”), not the data: Promise { <pending> }.

Errors with await: try / catch

If the database fails (wrong password, MySQL turned off, a typo in SQL), the await line throws an error. Catch it, or your request breaks:

const retrieveAllUsers = async (req, res) => {
  try {
    const [users] = await db.query('SELECT * FROM USERS');
    return res.status(200).json({ status: 'success', results: users.length, data: users });
  } catch (error) {
    console.error(error);   // print the real reason in YOUR terminal (very useful!)
    return res.status(500).json({ message: 'Database error' });  // a simple message for the client
  }
};
Practice 5.2

Connecting to MySQL

Install two more packages in your project:

npm install mysql2 dotenv
  • mysql2 — lets Node talk to MySQL.
  • dotenv — reads secret settings (like your database password) from a file called .env.

The .env file: settings and secrets

Make a file called exactly .env in the main project folder (next to server.js):

.env
HOSTNAME=localhost
PORT=5000

DB_USER=root
DB_PASSWORD=the_password_you_wrote_down
DB_NAME=travel_db

dotenv.config() reads this file and puts every line into process.env. So process.env.DB_PASSWORD becomes your password — without the password being written in your code.

Never upload .env

Make a file .gitignore with these two lines, so Git never uploads them:

node_modules
.env

db.js: the connection

db.js
const mysql = require('mysql2/promise');   // the /promise version works with await
const dotenv = require('dotenv');
dotenv.config();                           // load .env into process.env

const db = mysql.createPool({
  host: 'localhost',
  port: 3306,                              // MySQL's default port
  user: process.env.DB_USER,
  password: process.env.DB_PASSWORD,
  database: process.env.DB_NAME
});

const createTripTable = `CREATE TABLE IF NOT EXISTS TRIPS (
  ID INT AUTO_INCREMENT PRIMARY KEY,
  DESTINATION VARCHAR(150) NOT NULL,
  COUNTRY VARCHAR(150) NOT NULL,
  COST DECIMAL(10,2) NOT NULL
)`;

module.exports = { db, createTripTable };

A pool is a group of ready connections to the database, like a taxi rank: when your code needs to talk to MySQL, it takes a free “taxi” and gives it back afterwards. You don't need to manage it — just use db.query(...).

The CREATE TABLE text is SQL. You'll learn it properly in Chapter 6. For now: it describes the table's columns, and IF NOT EXISTS means “only create it the first time”.

server.js: create tables, then start

server.js
const { app } = require('./index.js');
const { db, createTripTable } = require('./db.js');
const dotenv = require('dotenv');
dotenv.config();

async function startServer() {
  try {
    await db.query(createTripTable);        // 1. make sure the table exists
    console.log('Trips table created or already exists.');

    app.listen(process.env.PORT, process.env.HOSTNAME, () => {   // 2. THEN start
      console.log(`Server is running at http://${process.env.HOSTNAME}:${process.env.PORT}`);
    });
  } catch (error) {
    console.error('Error initializing the database:', error);
    process.exitCode = 1;   // tell Windows "the program failed"
    await db.end();         // close the database connections
  }
}

startServer();

db.query: the one function you'll use all the time

const [rows] = await db.query(sql, [values]);
  • db.query gives back an array of two things: [rows, fields]. You only need the first, so you destructure it: const [rows] = ... (Chapter 1, section 8!).
  • For SELECT, rows is an array of objects — one per row. The keys are the column names: rows[0].DESTINATION.
  • For INSERT / UPDATE / DELETE, you get an info object instead: result.insertId (the new row's id) and result.affectedRows (how many rows changed).
  • The ? in the SQL are placeholders. MySQL puts the values from the array into them, safely. Always use them for values from the user — Chapter 7 shows why.
// SELECT → rows
const [trips] = await db.query('SELECT * FROM TRIPS WHERE ID = ?', [id]);
// trips = [ { ID: 2, DESTINATION: 'Rome', COUNTRY: 'Italy', COST: '950.50' } ]  ← or [] if none

// INSERT → result info
const [result] = await db.query(
  'INSERT INTO TRIPS (DESTINATION, COUNTRY, COST) VALUES (?, ?, ?)',
  [destination, country, cost]
);
console.log(result.insertId);     // e.g. 8
console.log(result.affectedRows); // 1
Small detail

Real MySQL returns DECIMAL columns (like COST) as text: "950.50". The playground returns a number: 950.5. Both are fine for this course.

Practice 5.4

GET /trips/:id with validation

A good “get one” controller checks three things:

  1. Is the id valid? Number("abc") is NaN; -5 and 2.5 make no sense either. Number.isSafeInteger(id) && id > 0 checks all of that. If invalid → 400.
  2. Did the database find it? trips.length === 0 → 404.
  3. Otherwise → 200 with trips[0] (the first and only row — not the whole array).

Practice 5.6

DELETE /trips/:id

For DELETE you don't need to SELECT first: result.affectedRows tells you how many rows were deleted. 0 means the id didn't exist → 404.

Try DELETE /trips/1 after it works: you get a 500, and the terminal says “a foreign key constraint fails”. Trip 1 has reviews pointing at it, and MySQL protects them. Chapter 8 explains this.

Problems connecting?
  • ER_ACCESS_DENIED_ERROR → wrong DB_USER/DB_PASSWORD in .env, or dotenv.config() runs after createPool.
  • ER_BAD_DB_ERROR: Unknown database → the database doesn't exist yet. Run CREATE DATABASE travel_db; in Workbench.
  • ECONNREFUSED 127.0.0.1:3306 → MySQL isn't running. Start the MySQL service (Chapter 0).
  • Everything is undefined → is the file called exactly .env (not .env.txt) and is it in the main folder?
