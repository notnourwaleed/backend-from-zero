Chapter 0

Set up your computer

Before writing a server you need the right tools. This chapter starts from absolute zero: how to make a file, how to open a terminal, how to install everything.

What you need (and why)

You already have some of these?

Great — skim those sections and do the check at the end anyway. It takes one minute and catches problems early.

1. Install VS Code

  1. Go to code.visualstudio.com and click the big Download for Windows button.
  2. Open the downloaded file. Accept the agreement and click Next.
  3. On the “Select Additional Tasks” screen, tick all of these:
    • Add “Open with Code” action to Windows Explorer file context menu
    • Add “Open with Code” action to Windows Explorer directory context menu
    • Add to PATH
    These let you right-click a folder → Open with Code.
  4. Click Install, then Finish.

2. VS Code basics: folders, files, saving

In VS Code you always work inside a folder — one folder per project. All your project files live in that folder.

Open a project folder

  1. On your Desktop, make a new folder (right-click → New → Folder) and name it my-backend.
  2. In VS Code: File → Open Folder… → choose my-backend → Select Folder.
  3. If it asks “Do you trust the authors of the files in this folder?”, click Yes, I trust the authors (it's your own folder).

On the left you now see the Explorer panel (if not, press Ctrl+Shift+E). At the top of it there's the folder name and four small icons when you hover over it:

📄+New File — click it, type a name like hello.js, press Enter.
📁+New Folder — for example routes.
⟳Refresh
⊟Collapse all folders
Making a file inside a folder

Click on the folder first (for example routes), then click New File. The new file is created inside the selected folder. You can also type a path directly: routes/userRoutes.js creates the folder and the file at once.

The file name ending matters

The part after the dot is the extension. It tells VS Code (and Node) what kind of file it is: .js = JavaScript, .json = JSON data, .md = notes. A file called .env (only an ending, no name) is normal — it's for secret settings, you'll see it later.

Saving

Press Ctrl+S to save. A white dot on the file's tab means “not saved yet”. Unsaved code does not run! Tip: turn on File → Auto Save so you never forget.

The terminal inside VS Code

Open it with Ctrl+` (the key under Esc) or Terminal → New Terminal. It opens at the bottom, already inside your project folder. You'll see something like:

PS C:\Users\you\Desktop\my-backend>

That's the prompt: the terminal is waiting for a command. Type a command and press Enter. Useful ones:

CommandWhat it does
dir (or ls)List the files in the current folder
cd routesGo into the folder routes
cd ..Go back up one folder
mkdir controllersMake a new folder
cls (or clear)Clear the screen
↑ arrowBring back the last command (saves typing!)
Ctrl+CStop the running program (for example, your server)
Quiz

You made changes to your code, but nothing is different when you run it. There is a white dot on the file tab. What's wrong?

The white dot means “unsaved changes”. Node runs the file that is saved on the disk, not what you see in the editor.

3. Install Node.js (with npm)

  1. Go to nodejs.org. Download the LTS version (LTS = “Long Term Support”, the stable one). Choose the Windows Installer (.msi).
  2. Run it. Click Next through the screens. Keep the default options (they include npm and Add to PATH).
  3. The screen “Tools for Native Modules” — you can leave it unticked.
  4. When finished, close VS Code completely and open it again. A terminal only knows about programs that were installed before it opened.
  5. In a new terminal type these two commands:
node -v
npm -v

You should see version numbers, like v22.11.0 and 10.9.0. Any numbers are fine.

Error: “npm.ps1 cannot be loaded because running scripts is disabled”

Very common on Windows. VS Code's terminal is PowerShell, which blocks some scripts by default. Two ways to fix it — choose one:

  1. Easiest: In the terminal panel, click the small ⌄ next to the + and choose Command Prompt. Use that terminal. (To make it the default: Ctrl+Shift+P → “Terminal: Select Default Profile” → Command Prompt.)
  2. Or allow scripts for your own user only. Run this once in PowerShell: 
    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
Error: “node is not recognized as an internal or external command”

Either Node is not installed, or the terminal was opened before the install. Close all VS Code windows and open it again. If it still fails, restart your computer.

Your first JavaScript program

  1. In your my-backend folder, make a new file called hello.js.
  2. Type this in it and save: 
    console.log("Hello from Node!");
console.log(2 + 3);
  3. In the terminal run: 
    node hello.js
  4. You should see Hello from Node! and 5. 🎉 You just ran JavaScript outside a browser.

node + a file name = “Node, please run this file”. That is exactly how you will start your server later: node server.js.

4. npm and packages

A package is code someone else wrote that you can use. Express (for building servers) is a package. npm downloads packages for you.

Every new project starts with:

npm init -y

This creates package.json — your project's “ID card”: its name and the list of packages it needs. (-y means “yes to all questions”.)

Then install packages:

npm install express

Three things happen:

  • A folder node_modules appears — the downloaded code. Never edit it, never upload it.
  • package.json gets a "dependencies" list with "express" in it.
  • A file package-lock.json appears — exact versions. Leave it alone.

You can install several packages at once. For the full course project:

npm install express mysql2 dotenv bcrypt cookie-parser
Got someone else's project?

It won't have node_modules (it's never shared). Just run npm install with no package name — npm reads package.json and downloads everything.

Quiz

Which folder should you NEVER upload to GitHub or send to friends?

node_modules is huge and can be re-created any time with npm install. You'll put it in a file called .gitignore so Git skips it.

You start a brand new project folder. What is the first npm command?

npm init -y creates package.json. After that you install packages.

5. Install MySQL Server and Workbench

You need two things: the MySQL Server (the database, runs in the background) and MySQL Workbench (the window to look into it).

  1. Go to dev.mysql.com/downloads/mysql. Choose Microsoft Windows and download the MSI Installer. (On the next page, click “No thanks, just start my download”.)
  2. Run it with the default (Typical) setup. At the end, the MySQL Configurator opens.
  3. In the Configurator: keep Development Computer and port 3306.
  4. Set a root password. Write it down! You'll need it in Workbench and in your project's .env file.
  5. Keep “Configure MySQL Server as a Windows Service” and “Start the MySQL Server at System Startup” ticked. Then MySQL is always running in the background.
  6. Click through to Execute and Finish.
  7. Now go to dev.mysql.com/downloads/workbench and install MySQL Workbench the same way.
Older guides

Older videos show one big “MySQL Installer” that installs everything together. Newer versions install the server and Workbench separately. Both ways work.

Create your database

  1. Open MySQL Workbench. Under “MySQL Connections” click Local instance MySQL… and enter your root password.
  2. A query tab opens. Type: 
    CREATE DATABASE travel_db;
  3. Click the ⚡ lightning icon (or press Ctrl+Enter) to run it.
  4. On the left, in the Schemas panel, click the refresh icon. You should see travel_db. (“Schema” is MySQL's word for “database”.)

That's all for now — you'll create the tables from your Node code in Chapter 5.

Error later: ECONNREFUSED 127.0.0.1:3306

This means MySQL Server is not running. Press Win, type Services, open it, find MySQL (for example “MySQL84”), right-click → Start.

6. Install Postman (to test your server)

A browser can only easily send GET requests (open a URL). To test POST, PUT and DELETE, you need a tool. We use Postman.

  1. Go to postman.com/downloads and download the Windows app. Run the installer — it installs and opens by itself.
  2. It asks you to sign in or create a free account. You can make one, or look for the small “Continue without an account” / “Skip” link (it moves around between versions).
  3. To make a request: click New → HTTP (or the + next to the open tabs). You'll use it from Chapter 3.
Keep your requests

Make a Collection (left side → Collections → +), name it “Travel API”, and save each request into it (Ctrl+S). Then you can re-send all your tests with one click every time you change your code.

7. Final check

Tick these off. They're saved in your browser.

  • VS Code is installed and I can open a folder with File → Open Folder
  • I can make a new file and a new folder in the Explorer
  • I can open the terminal with Ctrl+`
  • node -v prints a version number
  • npm -v prints a version number (no “scripts disabled” error)
  • node hello.js prints “Hello from Node!”
  • MySQL Workbench connects to my Local instance with my root password
  • The database travel_db exists
  • Postman is installed and I can open a new request
Quiz

Your server is running in the terminal and you can't type new commands. How do you stop it?

Ctrl+C stops the running program. A running server “takes over” the terminal. That's normal: it's waiting for requests.
