Routes & controllers: splitting your code into files

One big server.js gets messy fast. Real projects split the code into small files, each with one job. This is the structure your final project will use.

The folder structure

my-backend/ ├── server.js ← starts the server (app.listen) ├── index.js ← creates the app and connects the routers ├── routes/ │ └── userRoutes.js ← "which URL runs which function" ├── controllers/ │ └── userController.js ← the functions that do the work └── models/ └── User.js ← the data (later replaced by db.js + MySQL)
Back to the restaurant

The routes file is the waiter's list: “table orders pizza → send to the pizza cook”. The controller is the cook who actually makes it. The waiter never cooks, and the cook never takes orders. Each file has one job, so you always know where to look.

module.exports and require: sharing between files

Every file is closed by default: its variables are private. To share something, the file must export it, and the other file must require it.

math.js
const add = (a, b) => a + b;
const secret = 42;            // not exported → other files can't see it

module.exports = { add };     // "this file gives away: add"
main.js
const { add } = require('./math');   // "give me add from math.js"
console.log(add(2, 3));              // 5

The path rules:

You writeMeaning
require('express')No dot → a package from node_modules
require('./math')./ → a file in the same folder (the .js is optional)
require('../models/User')../ → go up one folder, then into models

Two ways to export, both common in your course:

module.exports = { retrieveAllUsers, createUser };  // an object with several things
// → other file: const { retrieveAllUsers, createUser } = require('../controllers/userController');

module.exports = userRouter;                         // just ONE thing
// → other file: const userRouter = require('./routes/userRoutes');   (no { } !)

express.Router(): a mini app for one topic

A router holds all routes for one topic (users, trips…). Inside the router, paths are relative. In index.js you plug the router in at a starting path:

routes/userRoutes.js
const express = require('express');
const { retrieveAllUsers, retrieveUserById } = require('../controllers/userController');

const userRouter = express.Router();

userRouter.get('/', retrieveAllUsers);      // → GET /users
userRouter.get('/:id', retrieveUserById);   // → GET /users/:id

module.exports = userRouter;
index.js
const express = require('express');
const userRouter = require('./routes/userRoutes');

const app = express();
app.use(express.json());

app.use('/users', userRouter);   // every route in userRouter now starts with /users

module.exports = { app };

Final URL = the prefix in app.use + the path in the router: '/users' + '/:id' = /users/:id.

Notice: in the routes file we pass the function's name — retrieveAllUsers, no (). We're handing the function to Express to call later, not calling it now (remember Practice 1.7).

Controllers

A controller is just a function (req, res) => { ... } with a clear name, saved in a variable and exported. Exactly the same code you wrote in Chapter 3, only moved:

controllers/userController.js
const { users } = require('../models/User');

const retrieveAllUsers = (req, res) => {
  res.status(200).json({ status: 'success', results: users.length, data: users });
};

module.exports = { retrieveAllUsers };

Why separate index.js and server.js?

index.js builds the app; server.js starts it. Keeping them apart means other code (like automatic tests) can load the app without starting a real server. It also keeps server.js tiny: later it will also create the database tables before starting.

server.js
const { app } = require('./index.js');

app.listen(3000, '127.0.0.1', () => {
  console.log('Server is running on port 3000');
});

Route order matters!

Express checks routes from top to bottom and uses the first one that matches. /:id matches anything — including words like admins or last-viewed.

router.get('/:id', retrieveUserById);  // GET /users/admins matches HERE (id = "admins")
router.get('/admins', getAdmins);      // never reached!

Rule: put fixed paths (/admins, /managers, /last-viewed) above /:id.

This bug is in the course code

In the week 8 code, /managers, /last-viewed, /reviews and /ratings are all written after /:id, so they never run. Now you know why — and you won't make that mistake in your project.
