SQL basics

SQL is the language you use to talk to MySQL. You write it as text inside db.query("..."). Here you practise it directly on a real practice database.

Tables, rows, columns

A database is a set of tables. A table is like a spreadsheet: columns are the kinds of information, rows are the items. Here's the TRIPS table from the practice database:

CREATE TABLE, explained line by line

This is the USERS table from the course:

CREATE TABLE IF NOT EXISTS USERS (
  ID INT AUTO_INCREMENT PRIMARY KEY,
  USERNAME VARCHAR(255) NOT NULL,
  EMAIL VARCHAR(255) UNIQUE NOT NULL,
  PASSWORD VARCHAR(255) NOT NULL,
  ROLE ENUM('admin', 'user') NOT NULL DEFAULT 'user',
  MANAGER_ID INT NULL,
  FOREIGN KEY (MANAGER_ID) REFERENCES USERS(ID)
);
PieceMeaning
IF NOT EXISTSOnly create it if it isn't there yet (so restarting your server is safe)
INTWhole number
VARCHAR(255)Text, up to 255 characters
DECIMAL(10,2)Exact number with 2 decimals — for money
ENUM('admin','user')Only these values are allowed
PRIMARY KEYThe column that identifies each row. Never repeats.
AUTO_INCREMENTMySQL picks the next number for you (1, 2, 3…) — you never send the ID
NOT NULLMust have a value
UNIQUENo two rows can have the same value (one account per email)
DEFAULT 'user'If you don't send a value, use this one
FOREIGN KEY … REFERENCESThis column points at a row in another table (Chapter 8)
Uppercase?

SQL words (SELECT, FROM) work in any case. Writing them in UPPERCASE is a habit that makes queries easier to read. Your course writes table and column names in uppercase too, so that's what the rows' keys look like in JavaScript: user.USERNAME.

SELECT: reading data

SELECT * FROM TRIPS;                          -- every column, every row
SELECT DESTINATION, COST FROM TRIPS;          -- only some columns
SELECT * FROM TRIPS WHERE COUNTRY = 'Italy';  -- only rows that match
SELECT * FROM TRIPS WHERE COST < 1000 AND COUNTRY = 'Italy';
SELECT * FROM TRIPS ORDER BY COST DESC;       -- sort: ASC = small→big, DESC = big→small
SELECT * FROM TRIPS LIMIT 3;                  -- only the first 3
SELECT DESTINATION AS place FROM TRIPS;       -- rename a column in the result
SELECT * FROM TRIPS WHERE DESTINATION LIKE 'K%';  -- starts with K  (% = "anything")

Text values go in single quotes: 'Italy'. Numbers don't. Lines starting with -- are comments.

INSERT: adding a row

INSERT INTO TRIPS (DESTINATION, COUNTRY, COST)
VALUES ('Lisbon', 'Portugal', 780);

List the columns, then the values in the same order. Don't send the ID — AUTO_INCREMENT picks it.

In Node, the values are replaced by ? placeholders and sent separately:

await db.query(
  'INSERT INTO TRIPS (DESTINATION, COUNTRY, COST) VALUES (?, ?, ?)',
  [destination, country, cost]
);

UPDATE: changing rows

UPDATE TRIPS SET COST = 999 WHERE ID = 2;
UPDATE USERS SET USERNAME = 'sara_k', ROLE = 'user' WHERE ID = 1;   -- several columns
Never forget WHERE

UPDATE TRIPS SET COST = 0; with no WHERE changes every single row. Same for DELETE. There's no undo button. Always write the WHERE first.

What happens with DELETE FROM TRIPS; (no WHERE)?

Every row is deleted. (In real MySQL Workbench, “safe update mode” may block it — but your Node code has no such protection.)

Counting and grouping (bonus, very useful)

SELECT COUNT(*) FROM TRIPS;                               -- how many rows: 7
SELECT AVG(COST) FROM TRIPS;                              -- average
SELECT COUNTRY, COUNT(*) AS trips FROM TRIPS GROUP BY COUNTRY;   -- one row per country

GROUP BY COUNTRY puts all rows with the same country into one group, and COUNT(*) counts each group.

One more thing: ? placeholders

When SQL is in your Node code, the values usually come from the user (req.body, req.params). Never glue them into the SQL text yourself:

// ❌ DANGEROUS — the user's text becomes part of your SQL
db.query(`SELECT * FROM USERS WHERE EMAIL = '${email}'`);

// ✅ SAFE — MySQL treats the value as data, never as SQL
db.query('SELECT * FROM USERS WHERE EMAIL = ?', [email]);

Chapter 7 shows you exactly how an attacker breaks the first version. For now: values always go in ?.
